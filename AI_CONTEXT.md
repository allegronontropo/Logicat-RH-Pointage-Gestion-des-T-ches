## Two critical dependencies (implement exactly this way)
```python
# 1. get_current_user — ALWAYS queries DB, ALWAYS checks is_active
#    Returns 401 if token invalid, expired, or account inactive.
def get_current_user(token: str = Depends(oauth2_scheme), db: Session = Depends(get_db)) -> User:
    payload = decode_jwt(token)          # raises 401 on failure
    user = db.get(User, payload["sub"])  # raises 401 if not found
    if not user or not user.is_active:   # raises 401 if inactive
        raise HTTPException(401)
    return user

# 2. get_current_employee — wraps get_current_user; derives identity from token ONLY
def get_current_employee(current_user: User = Depends(get_current_user), db: Session = Depends(get_db)) -> Employee:
    employee = db.scalar(select(Employee).where(Employee.user_id == current_user.id))
    if not employee:
        raise HTTPException(403)
    return employee
```

## Hard constraints — NEVER violate
- No public registration endpoint (`POST /signup` must not exist).
- No refresh tokens. No OAuth. No email flows. No magic links.
- JWT: HS256 · 30-minute expiry · payload = `{sub: user_id, role: role}`.
- All timestamps: `datetime.now(timezone.utc)` server-side. NEVER accept client times.
- Timezone: store UTC · compute "today" with `Africa/Casablanca`.
- `is_active` checked in DB on EVERY protected request (not cached in JWT).
- Admin cannot deactivate self OR the last active ADMIN_RH (transaction + count).
- Employee profile update: only `phone` and `password` fields — use a separate Pydantic schema.
- Task status update (employee): only `status` field — use a separate Pydantic schema.
- Attendance timestamps generated by server — `request.body` must never contain time fields for check-in/break/check-out.

## Database schema (5 tables — FK chain is strict)
```
users       → employees (1:1, EMPLOYEE role only)
employees   → attendances (1:many, employee_id FK)
attendances → breaks (1:many, attendance_id FK)
employees   → tasks.assigned_to (FK)
users       → tasks.created_by  (FK)
```
Key constraints:
- `users.email` UNIQUE
- `employees.user_id` UNIQUE
- `UNIQUE(employee_id, date)` on attendances
- `UNIQUE(attendance_id, type)` on breaks
- Break types: MORNING · LUNCH · EVENING

## Attendance state machine (enforce in services, not routers)
NO_RECORD → [check-in] → CHECKED_IN → [start break] → ON_BREAK → [end break] → CHECKED_IN → [check-out] → DONE

Rules: check-in before any break or check-out · 1 check-in/day · 1 check-out/day ·
       1 active break at a time · check-out blocked during active break · each break type once/day ·
       employee cannot mutate past attendance.

## Working time formula
presence = check_out − check_in
breaks_total = Σ(end_time − start_time)
effective = presence − breaks_total
